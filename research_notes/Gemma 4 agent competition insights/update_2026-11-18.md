### ADK template braces in the system prompt

**Literal `{…}` in `prompts/system.md` can zero the whole run** — [CLAIM pablodiegoo, [starter notebook v14, 11-18 11:37](https://www.kaggle.com/code/pablodiegoo/gemma-4-developer-agent-starter-notebook)]
- His v13 bundle (40 calls / 8 min / 80 turns / 120 s, 6 tools, prompt containing `{problem_description?}` / `{hints?}`) scored **0.00**. Total output was 3,230 bytes, meaning empty patches.
- v14 therefore removes every `{`/`}` from the prompt and validates the prompt against an allowed set of ADK state variables.
- He gives no single cause, and his "regime" pass-rate table is hard-coded modelling, not measurement.
- [I] ADK treats `{name}` in the instruction as a state lookup, so any unknown or unbalanced brace can break the agent.
- Our check: `candidates/v6`, `v4` and `p1-*` contain no braces. Only `candidates/v3` uses `{problem_description}` / `{hints?}`.

### The edit_file / backtick failure: root cause

**Tool arguments are sorted alphabetically, so new_string comes before old_string** — [MEASURED Nir Aberman, [T758968](https://www.kaggle.com/competitions/gemma-4-developer-agent/discussion/758968), ~11-13]
- The edit_file failures where old_string is lost when the edit contains a backtick come from the chat template sorting tool arguments alphabetically. As a result, `new_string` is rendered before `old_string`.
- Fixing this removed the broken calls from his archive but **did not raise solves**.
- [I] This matches our own analysis of argument order in `skills_and_edit_failures.md`.

**Prompt-level workarounds (no leaderboard evidence for either)**
- pablodiegoo v14: anchor edit_file on lines free of `"` and backticks. Otherwise, or after two failed matches, use `python3 - <<'EOF'` and assert `content.count(old) == 1`.
- tuijiaaa ([Budget-Aware Optimized v1](https://www.kaggle.com/code/tuijiaaa/gemma-4-budget-aware-optimized-v1), 11-18 05:12) has a similar fallback rule. Its bundle is Budget-Fit-like: 9 tools with graph use forbidden, 0.2 / 0.95 / 8192 / 4096, 240 s / 28 calls / 8 min / 80 turns, "edit by call 12". No score is claimed.

### Variance and determinism

**temperature 0 does not remove run-to-run variance** — [MEASURED Japan OpenData Lab, [T760014](https://www.kaggle.com/competitions/gemma-4-developer-agent/discussion/760014) reply ~11-18 05:00]
- Setup: E4B, 114 local tasks.
- At **temperature 0.0**, solved counts across **10 identical full runs** ranged **11–15 (SD 1.52)**.
- Their explanation: continuous batching changes the order of reductions between runs.

**Five zero-weight LoRA submissions all scored 0.15** — [MEASURED-LB xz, T759514]
- Setup: a public notebook with temperature 0.2, submitted 5 times, each scoring 0.15.
- Others replied that the same public notebook spans 0.13–0.20 (Ankith Savio) or "same 0.15" (VELVRIN).
- [I] One identical 5/5 streak against the reported spread is odd, but n = 5 is too small to infer caching.

**LoRA kernels are non-deterministic; split_k=1 fixes it** — [MEASURED-synthetic SalmanS24, T751311]
- In the competition's vLLM 0.19.1 wheel, the LoRA shrink kernel defaults to split-K 64 (for batch < 128) with relaxed atomics.
- In a synthetic single-L4 test with 200 calls per shape, this produced 66–200 distinct outputs per 200 calls.
- With `split_k=1`, every case was bitwise identical.
- The scorer environment is fixed, so participants cannot use this.

**Five-and-a-half minutes per task gave no clear gain** — [MEASURED Sum YEUNG, [T759154](https://www.kaggle.com/competitions/gemma-4-developer-agent/discussion/759154)]
- 5.5 vs 4 min per task: +1.6 points on 129 training tasks (95% CI −1.6 to +4.7).
- A code-context skill and self-written lessons did not help.
- The same zip has scored anywhere from 0.12 to 0.17.
